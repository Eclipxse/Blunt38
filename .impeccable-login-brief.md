# Dashboard Login

## Scope and Mode

- Surface: unauthenticated dashboard homepage in `dashboard/src/components/dashboard-login.tsx`.
- Mode: Persuade, with one action: authenticate through Discord.

## Audience and Job

- Existing blunt38 users who manage Discord servers.
- They need to recognize the product, trust that the OAuth route is ready, and enter the dashboard immediately.

## Content and Constraints

- Preserve the existing `/api/auth/login` action and all authentication error states.
- Keep the aggressive, uncensored voice.
- Keep the watcher reactive but visually secondary.
- Do not add fabricated metrics or turn the portal into a long marketing page.
- Support mobile layouts and reduced motion.

## Direction

- Chosen direction: Signal Hijack, explicitly approved by the user.
- Memorable moment: a full-screen `BLUNT38` wordmark fills from the bottom with moving signal liquid, then clears upward into the login surface.
- First viewport: aggressive copy and Discord CTA on the left, watcher transmission on the right, capability status rail along the bottom.
- No generated composition was used; the direction was implemented in code and approved through desktop and mobile render inspection.

## Implementation Fidelity

| Ingredient | Medium | Commitment |
| --- | --- | --- |
| Liquid wordmark boot | Semantic text, CSS clipping, React progress | Full viewport, readable percentage, short exit transition |
| Particle masthead | Existing canvas component | Wide low-opacity field behind the page |
| Login action | Semantic anchor and Lucide icons | Highest-contrast control in the viewport |
| Watcher | Existing raster channels and interaction component | Right-side secondary presence; compact on mobile |
| Signal rails | Semantic status text and CSS rules | Edge-aligned, unframed, no invented metrics |
